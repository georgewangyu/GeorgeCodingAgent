# GeorgeCodingAgent

A coding agent for Claude Code and other tools: a `coding` worker, a read-only `reviewer`, and the plan, build, verify, review and ship skills they use. It works on its own. Each skill is tagged by how likely it is to survive better models.

Pair it with [JarvisAIGeorge](https://github.com/georgewangyu/JarvisAIGeorge) for the manager and fleet.

## Install

Claude Code:

```sh
claude plugin marketplace add georgewangyu/GeorgeCodingAgent
claude plugin install george-coding-agent@george-coding-agent
claude --agent george-coding-agent:coding
```

Review in a fresh, read-only context: `claude --agent george-coding-agent:reviewer`, or from the coding agent through `code-review-and-quality` and `doubt-driven-review`.

Codex (CLI 0.122 or later):

```sh
codex plugin marketplace add georgewangyu/GeorgeCodingAgent
codex plugin add george-coding-agent@george-coding-agent
codex   # then: "Load $role-coding first. <task>"
```

Codex has no agent files, so a worker takes its role from a skill: `$role-coding` or `$role-reviewer` at the start of its prompt. The reviewer's read-only tools are not enforced by the skill; run it as `codex exec --sandbox read-only 'Load $role-reviewer first. ...'` to enforce them. The coding role's review loop does this itself. Start a new Codex session after installing so the skills are discovered. Codex path status: manifests validated against Codex's schema, not yet run end to end.

Any tool, skills only: `npx skills add georgewangyu/GeorgeCodingAgent`.

Only a few skills stay in the tool's skill list (the router `george-coding-agent-skills`, the coding agent's preload skills and `code-review-and-quality`); the router names every other skill with its file, so the list stays small however many skills ship.

Optional skills from other plugins (`grill-me`, `brainstorm`, `mistake-miner`, the `principles*` skills) are used when installed and skipped when not.

## Layout

- `jarvis-extension.json`: the manifest (agents and skills). A manager that reads extension manifests can list this plugin from it.
- `agents-src/coding.md`, `agents-src/reviewer.md` and `agents-src/rules/`: the agent sources. Rules are inlined at build.
- `skills/`: the skills. `skills/role-coding` and `skills/role-reviewer` are generated.
- Generated, never hand-edit: `agents/`, `skills/role-*/`, `.claude-plugin/`, `.codex-plugin/`, `.agents/plugins/`, `AGENTS.md`, `CLAUDE.md`. Rebuild with `python3 tools/jarvis-build.py`; CI runs `--check`.
- `tools/bitter_lesson.py`: the bitter-lesson tag checker.
- [`tools/VENDORED.md`](tools/VENDORED.md): where each vendored tool comes from. CI fails if a vendored file changes without its hash in `tools/vendored.sha256`.
- `tools/ci/scrub-gate.sh <base>`: the CI scrub gate. The base commit's engine, config and marker lists judge the change, so a change cannot exempt itself by editing `.scrub-lint.conf`, the lists or the engine. Its baseline may only shrink (a first baseline needs a manual exception), and a base CI cannot find fails the gate. CI also runs the change's own config, and warns when a change edits the gate.

## Bitter-lesson tags

Each skill marks its parts with a short inline tag:

- `[bl: invariant]`: a rule of the game (a feedback signal, an eval, or a real invariant). Always follow.
- `[bl: strong]`: follow it. It should become a hard check or a learned example over time.
- `[bl: soft]`: guidance for weaker models. A strong model may skip it. Candidate to expire.

A `BITTER_LESSON.md` next to each `SKILL.md` holds the full analysis (why, review date, delete-when, ablation result). Agents only read it when evaluating skills, not at session start.

```sh
python3 tools/bitter_lesson.py check  --root .   # every tagged item has a row, and the reverse
python3 tools/bitter_lesson.py report --root .   # the cleanup list
python3 tools/bitter_lesson.py ablate --root .   # soft items to test with and without
```

Principle skills (`principles*`) are durable reasoning methods and carry no tags.

Expire by evidence: run the skill's eval with and without a soft item on a new model. If nothing changes, delete it. A skill whose items have all expired goes away.
